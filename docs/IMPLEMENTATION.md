# unote 产品与实现设计

本文是新版本 unote 的唯一行为基线。项目不考虑旧仓库格式迁移。

## 1. 产品定位

unote 是一个超级轻量、Git 优先的个人文档应用。真实文件和目录是唯一内容真相；Git 承担版本历史与多设备同步。应用不建立必须依赖专有数据库才能理解的内容模型，也不要求用户理解 branch、HEAD、rebase 等 Git 概念。

用户必须通过认证提供方登录。首版支持 Gitee，后续通过同一 seam 增加 GitHub、GitLab。

## 2. 仓库协议

专用仓库名称固定为 `<username>.<auth-provider>.unote`，例如 `alice.gitee.unote`，新仓库始终创建为私有仓库。

登录后：

- 远端不存在：创建私有仓库并初始化 unote。
- 远端为空：允许初始化。
- 远端包含有效 `.unote/settings.json`：打开并同步。
- 同名非空仓库不是有效 unote 仓库：登录失败，用户需在托管平台自行重命名或删除。
- 设置损坏或版本高于当前客户端：停止打开，不覆盖原内容。

```text
<repository>/
├─ .unote/
│  └─ settings.json
├─ .assets/
├─ .trash/
├─ 工作/
│  ├─ 项目/
│  │  ├─ 计划.md
│  │  ├─ 架构.excalidraw
│  │  └─ 产品.mindmap
│  └─ 周报.md
└─ 生活/
```

`.unote/settings.json` 只保存跨设备一致的仓库协议设置；首版仅需：

```json
{
  "schemaVersion": 1
}
```

自动同步、窗口状态、最近打开文档等设备偏好保存在操作系统应用数据目录，不进入 Git。

## 3. 路径与名称

- 仓库相对路径是文件夹和文档的唯一持久身份，不保存隐藏 ID。
- 文件夹可无限嵌套；真实目录树就是应用导航树。
- 重命名文件夹或文档必须重命名真实路径。
- 用户名称禁止以 `.` 开头，为系统文件保留点前缀名称空间。
- 拒绝路径分隔符、Windows 非法字符、尾随空格或点，以及 `CON`、`PRN`、`AUX`、`NUL`、`COM1` 等系统保留名。
- 非法名称必须拒绝并解释原因，不得静默改写。
- 创建或重命名发生冲突时使用可见编号：`周报.md`、`周报 (2).md`。
- 扫描器不跟随符号链接或 Windows Junction，不读取仓库外内容。

启动和窗口重新获得焦点时重新扫描真实目录。没有未保存编辑时载入外部变化；有未保存编辑时不覆盖内存内容，提示用户选择保留应用版本或载入磁盘版本。

启动扫描只枚举路径与必要元数据，正文按需读取。全文搜索需要加速时可以建立仓库外、可删除重建的本地索引；索引不得进入 Git，也不是真相来源。

## 4. 文档类型

### Markdown

`.md` 使用 CommonMark/GFM。编辑体验参考 MDXEditor 官方 Demo，提供富文本和源码模式；禁用 JSX、`import`、`export`、Sandpack 及自定义 React 组件语法。Mermaid 通过 fenced code block 表达。

标题来自文件名，不在正文重复保存。用于跨设备排序的 `updated_at` 存在 YAML 文件头；缺失或无效时回退到文件修改时间。

### 画布

`.excalidraw` 保存标准 Excalidraw JSON，由 Excalidraw 编辑器打开。排序优先使用内容中的更新时间，缺失时回退到文件修改时间。

### 脑图

`.mindmap` 保存可读的严格有根树 JSON：恰有一个根节点，其他节点恰有一个父节点。React Flow 只是编辑 adapter；文件不保存 React Flow 私有结构或布局坐标，布局可重新计算。

未来可增加按文档类型筛选；筛选不改变文件结构或同步方式。

## 5. 资源与回收站

`.assets/` 保存仓库级附件并保留真实文件名；重名时自动编号。Markdown 使用相对链接引用资源。删除或永久删除文档不得自动删除资源；未来可查找未引用资源，但只能由用户显式确认清理。

删除文件夹或文档时，将真实路径移动到 `.trash/` 并保留原相对结构。恢复时移回原位置；目标重名时自动编号。永久删除只删除 `.trash/` 中的真实路径。

## 6. 保存与同步

本地保存只写文件，不提交、不联网。输入采用短防抖保存。

同步由用户手动触发或设备本地定时器触发；默认五分钟，可关闭。同步前必须等待当前本地保存完成。同步执行时不得持有阻塞编辑的全局状态锁。

同步流程：

1. 完成本地保存。
2. 有变化则创建本地 Git 提交。
3. fetch 远端。
4. 无冲突变化自动合并并 push。
5. 同一 Markdown 的非重叠修改尝试三方合并。
6. 无法安全合并时保留两个普通文件，以设备和时间后缀区分。
7. `.excalidraw`、`.mindmap` 同时修改时不做结构级猜测，直接保留冲突副本。
8. 删除与另一端新修改冲突时，新修改获胜并恢复文档。
9. 自动创建合并提交并继续同步；永不强推，永不静默丢弃任一版本。

界面只使用“同步中”“已同步”“发现冲突，两个版本均已保留”等产品语言，不暴露 Git 内部术语。

## 7. 凭据与平台

token 不写入仓库或明文设备文件。Windows 使用 Credential Manager，macOS 使用 Keychain，Linux 使用 Secret Service。Linux 缺少安全凭据存储时，仅允许当前进程内存会话，关闭应用后重新登录，绝不降级为明文持久化。退出登录删除凭据，但保留本地仓库。

首版以 Windows 为主要开发和人工验收平台。文件协议、名称校验和凭据 seam 从第一天兼容 Windows、macOS、Linux，并通过三平台 CI 编译检查；macOS/Linux 正式安装包的人工验收可后置。

## 8. 前端技术

- React 19
- Vite 8（Node.js 20.19+ 或 22.12+）
- shadcn/ui + Tailwind CSS
- MDXEditor：普通 Markdown/GFM 富文本与源码编辑
- Excalidraw：画布编辑
- React Flow：脑图编辑

前端通过显式、类型化的 workspace interface 隔离桌面运行时，不通过返回值形状猜测状态。当前框架只接内存 adapter；Rust workspace interface 稳定后再实现并接入 Tauri adapter，避免伪造尚不存在的命令契约。编辑器 adapter 只产生文档内容变化；路径、保存、冲突和同步由 Rust 端深 module 负责。

## 9. 非目标

- 任意本地 Git 仓库入口
- 私有数据库或隐藏内容索引
- 持久化文档 ID
- MDX/JSX 文档
- 实时多人协作
- 自动强推或静默丢弃冲突版本
- 首版自动删除未引用资源
- 旧仓库格式迁移
